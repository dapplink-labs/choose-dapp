# 收益页 UI 换壳设计

## 背景

本次改造目标是将“节点收益页”和“质押收益页”统一重构为新的移动端黑金视觉风格，严格贴合当前设计稿风格，但不改动后端接口、路由、交互逻辑、数据计算逻辑和领取收益等业务流程。

目标页面：

- `src/views/myNode/index.vue`
- `src/views/myIncome/index.vue`

设计稿范围：

- `new_designs/H5-暗-节点-节点收益-直推.png`
- `new_designs/H5-暗-质押-质押收益-直推.png`

已确认约束：

- 本轮只做前端 UI 和布局重构
- `direct` 和 `team` 使用同一套视觉样式
- `direct` 与 `team` 的差异仅保留在顶部人数统计文案
- 图标优先复用 `src/assets/new_icon/LPVault` 目录下已有资源
- 当前阶段不抽离成新的通用业务组件，不合并两个页面的数据逻辑

## 方案选择

采用方案 B：

- 保留两个页面各自现有的数据获取、字段映射、跳转、领取收益、切 tab 等逻辑
- 统一两个页面的视觉骨架和样式规范
- 通过共享布局结构、共享 class 命名和共享局部样式，降低两页视觉分叉风险

不采用方案 C（完全组件化重构）的原因：

- 两页当前字段结构和顶部业务语义存在差异
- 现阶段目标是换壳，不宜同时进行高风险的结构性抽象

## 页面结构设计

两个页面统一收敛为以下视觉层次：

1. 顶部品牌卡片区
2. 收益概览卡片区
3. 进度展示区
4. 待领取收益区
5. 主操作按钮区
6. 团队模块区

### 顶部品牌卡片区

保留原有页面标题、节点名称、等级、购买时间、激活状态等业务信息，但改为新设计稿的深色卡片式承载方式。

要求：

- 去掉旧版浅色背景和松散布局
- 使用黑色系背景、圆角、描边或弱分割提升层级感
- 标题、状态、时间等排版遵循设计稿的字号和留白
- 保留切换节点入口和记录入口等现有行为

### 收益概览卡片区

两个页面顶部收益统计统一为 2 列或 2 宫格卡片样式，使用相同视觉语言：

- 主数值突出
- 辅助估值次级显示
- 图标尺寸和间距统一
- 卡片圆角、边框、阴影、背景统一

节点收益页和质押收益页的数据项允许不同，但卡片外观必须统一。

### 进度展示区

保留现有进度计算逻辑，仅重构视觉：

- 使用设计稿的深色进度轨道
- 黄色进度填充保持全站统一主题色
- 剩余可领取提示气泡、左右数值、单位样式统一
- 气泡位置继续沿用现有百分比定位逻辑

### 待领取收益区

重构为设计稿中的深色信息卡片/分组列表样式：

- 标题栏与“领取记录”入口统一黑金风格
- 每个收益项使用统一信息单元样式
- 主值、辅助估值、标签文字的字号层级统一
- 节点收益页与质押收益页允许展示不同字段，但列表单元外观保持一致

### 主操作按钮区

沿用现有 `PrimaryActionButton`，但按设计稿校准：

- 高度
- 圆角
- 字重
- 上下留白
- 宽度与容器关系

按钮逻辑不变：

- 节点页保留弹窗打开逻辑
- 质押页保留跳转领取页逻辑
- 凌晨不可领取逻辑保持不变

### 团队模块区

`direct` 和 `team` 共用同一套视觉结构，仅在顶部统计文案上区分“直推”和“团队”语义。

要求：

- tab 样式统一成新稿风格
- 人数统计信息统一成同一行或同一组卡片式排版
- 团队树容器与列表容器统一边框、圆角、背景
- 地址列表项统一头像尺寸、地址排版、收益排版、时间/Upline 信息层级

## 图标资源策略

优先使用以下已有资源进行复用：

- `src/assets/new_icon/LPVault/lpvault-node-illustration.png`
- `src/assets/new_icon/LPVault/lpvault-records.png`
- `src/assets/new_icon/LPVault/lpvault-arrow-right.png`
- `src/assets/new_icon/LPVault/lpvault-share.png`

若单个图标语义不完全匹配，优先按视觉一致性使用，不新增临时风格不统一的旧图标。

## 实现边界

本轮允许修改：

- 两个页面的 template 结构
- 两个页面的 scoped 样式
- 页面中与视觉重构直接相关的静态资源引入

本轮不修改：

- API 调用
- 响应数据结构
- 路由
- 合约交互
- 领取收益逻辑
- TeamTree 组件内部逻辑
- 其它页面的收益相关 UI

## 错误处理与兼容策略

视觉重构过程中必须保持以下行为不变：

- 无数据时不报错
- 钱包未连接时不新增阻塞逻辑
- 领取收益按钮禁用逻辑不变
- `direct` / `team` tab 切换后的数据请求逻辑不变
- 弹窗打开关闭逻辑不变

如果设计稿与现有业务字段不完全对应，优先保持现有字段展示，只调整视觉承载方式，不补造新字段。

## 测试与验收

最小验收标准：

- 两个页面在移动端宽度下完成黑金风格换壳
- `direct` 和 `team` 页签视觉一致，仅统计文案不同
- 顶部卡片、收益卡片、进度区、待领取收益区、团队列表区都与旧版明显区分
- 现有领取、切换、跳转、团队切换逻辑可正常使用
- 项目 `pnpm build` 通过

## 实施顺序

1. 先改 `src/views/myNode/index.vue`
2. 再将同一套视觉规则迁移到 `src/views/myIncome/index.vue`
3. 统一微调两页按钮、卡片、字号、间距
4. 构建验证
